    Reference
    
                        
    What each mode compares, and what it does not.
    

                        
    Modes
    
                        
    
                            
    Effective permissions
    
                            
    Compares the access each side grants. Wildcards are matched by containment and an explicit Deny is applied.
    
                            
    As written
    
                            
    Compares how each side is phrased. Nothing is expanded and no Deny is applied, so s3:* and s3:GetObject are a difference.
    
                        
    

                        
    Normalization, both modes
    
                        
    
                            
    Sid
    
                            
    Ignored. A name is not a permission.
    
                            
    Order
    
                            
    Statement order and value order are ignored.
    
                            
    Single values
    
                            
    A bare value and a one-element array are equal, wherever IAM accepts a list.
    
                            
    Duplicates
    
                            
    Removed.
    
                            
    Account IDs and Regions
    
                            
    Replaced with tokens while the matching option is on. Turn the option off when the account or the Region is what you are checking.
    
                        
    

                        
    Effective permissions
    
                        
    
                            
    Unit
    
                            
    One permission: Effect, Action, Resource, Principal, Condition. Statements are flattened into these and deduplicated.
    
                            
    Wildcards
    
                            
    Matched by containment. A side granting s3:* covers the other side's s3:GetObject. Action names match case-insensitively, as IAM matches them; resources do not.
    
                            
    Explicit Deny
    
                            
    An Allow fully covered by a Deny is removed before the comparison. A Deny covering only part of an Allow, or carrying a Condition, is flagged on the row instead; subtracting it would require pattern arithmetic.
    
                            
    One-sided Deny
    
                            
    Counts against the side that declares it. The other side is missing a restriction, which makes the other side the wider one.
    
                            
    NotAction, NotResource
    
                            
    Compared literally. They describe a complement and cannot be expanded into permissions, so a difference may be larger than it appears.
    
                            
    Conditions
    
                            
    Compared structurally. Fewer accepted values under the same operator and key reads as narrower; a Not operator inverts this. Conditions are never evaluated.
    
                        
    

                        
    As written
    
                        
    
                            
    Unit
    
                            
    One block: a set of actions on a set of resources under one Effect, principal and condition.
    
                            
    Merging
    
                            
    Blocks start as the statements were written, then merge until nothing more can: same scope and different actions become one block with the actions unioned; same actions and different scope become one block with the resources unioned. How a policy was split up is therefore not a difference, in either direction.
    
                            
    Pairing
    
                            
    Blocks are matched by scope first, then by content similarity, strongest match first. An Allow is never paired with a Deny.
    
                            
    Moved actions
    
                            
    An action both sides list, but never under the same condition, is lifted into a block of its own on each side. Left merged it would read as a deletion in one block and an unrelated block appearing elsewhere. A resource added or dropped is not a move; it stays visible inside its block.
    
                            
    Output
    
                            
    A line diff of the two normalized documents. Within a pair of changed lines, the parts that actually differ are marked. Each block is labelled with the Sid it was written under.
