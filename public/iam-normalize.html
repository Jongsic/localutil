IAM Normalize

Merge the duplicate and overlapping statements in an AWS IAM policy into one canonical document

Both options are off by default because they make the result a comparison aid rather than a policy you can deploy.

    What it does
    
                        
    
                            
    Unit
    
                            
    One block: a set of actions on a set of resources under one Effect, principal and condition.
    
                            
    Merging
    
                            
    Blocks start as the statements were written, then merge until nothing more can: same scope and different actions become one block with the actions unioned; same actions and different scope become one block with the resources unioned.
    
                            
    Sorting
    
                            
    Every list is sorted and deduplicated, and object keys are written in a fixed order, so the same policy always comes out the same way.
    
                            
    Sid
    
                            
    Dropped. A name is not a permission, and merged blocks have no single name to carry.
    
                            
    Single values
    
                            
    A bare value becomes a one-element array, wherever IAM accepts a list. The two mean the same thing.
    
                        
    

                        
    What it does not do
    
                        
    
                            
    Wildcards
    
                            
    Left as written. s3:* is not expanded, and an action it covers is not removed — the two are different text and both are kept.
    
                            
    Deny
    
                            
    Left as written. A Deny is a block like any other and cancels nothing.
    
                            
    NotAction, NotResource
    
                            
    Kept on their own axis and never merged with the positive form.
    
                            
    Conditions
    
                            
    Sorted, never evaluated. Two blocks differing by a condition stay apart, and two ways of writing the same restriction stay different.
    
                            
    Nothing is dropped
    
                            
    Checked on every run, not just promised. Merging statements and expanding them into permissions are two different pieces of code; the second is run over the input and over the result, and the two sets have to be identical. The page says so either way and refuses to vouch for an output that fails — it does not try to patch one, because a policy assembled by code that has just been caught getting this wrong is not a policy to hand anyone. Both sides normalize values with the same helpers, so a defect in those would be invisible here; what this catches is a permission dropped, gained, or re-attached to the wrong scope.
